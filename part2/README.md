# 项目二：知识图谱构建

基于项目一抓取的人物词条，设计属性图 schema，用 **CasRel + DuIE2.0** 训练关系抽取模型，
从正文中抽取 SPO 三元组，写入图数据库，并提供 GUI 做文本抽取、指标查看与 Cypher 查询。

## 二、环境准备

Python 3.8+（本工程在 3.13 下运行），有 NVIDIA 显卡更好（RTX 4060 8GB 实测约 9 分钟/轮）。

```bash
pip install -r requirements.txt
```

## 三、完整流程

```bash
python main.py prepare    # 1) 转换 DuIE2.0 + 弱监督标注 + 划分数据集
python main.py train      # 2) 训练 CasRel（默认 6 轮，每轮约 9 分钟）
python main.py extract    # 3) 对项目一全部词条抽三元组
python main.py import     # 4) 写入图数据库
python main.py viz        # 5) 生成交互图谱与统计图
python main.py gui        # 6) 启动界面
```

训练不必跑满：每轮结束会打印 dev 的 P/R/F1，**F1 开始下降就可以停**（`best.pt` 始终是验证集最优那一轮）。
本项目实际跑到第 2 轮就停了，第 3 轮的 dev F1 反而回落，属于典型过拟合。

调试时可以先小样本跑通：`python main.py train --limit 2000 --epochs 1`。

## 四、属性图 schema

以「人物」为中心，**8 类节点、14 种节点-节点关系、11 个节点属性**，
完整表格与示意图见 [`docs/属性图Schema.md`](docs/属性图Schema.md)。

| 关系 | Subject | Object | 关系 | Subject | Object |
| --- | --- | --- | --- | --- | --- |
| 出生地 | 人物 | 地点 | 参演 | 人物 | 作品 |
| 籍贯 | 人物 | 地点 | 执导 | 人物 | 作品 |
| 国籍 | 人物 | 国家 | 编剧 | 人物 | 作品 |
| 民族 | 人物 | 民族 | 演唱 | 人物 | 作品 |
| 毕业院校 | 人物 | 机构 | 主持 | 人物 | 作品 |
| 经纪公司 | 人物 | 机构 | 获得奖项 | 人物 | 奖项 |
| 职业 | 人物 | 职业 | 合作 | 人物 | 人物 |

设计要点：

1. 所有边都从人物出发，查询「某人演过什么、拿过什么奖」只需一跳；
2. 关系方向与 DuIE 对齐时做过归一——DuIE 的「主演/导演/歌手/主持人」是「作品→人物」，训练前统一翻转；
3. `合作` 是唯一的人物-人物关系，用于把不同人物连成连通分量。

## 五、关系抽取方案

采用「**神经网络模型 + 规则模板**」组合（参考文档允许自由组合）：

### 5.1 训练数据

| 来源 | 条数 | 覆盖关系 |
| --- | ---: | --- |
| DuIE2.0（官方 train） | 67,368 | 参演、演唱、执导、国籍、毕业院校、编剧、主持、获得奖项、籍贯 |
| 项目一弱监督 | 1,516 | 职业、出生地、合作、民族、经纪公司 |

DuIE2.0 的 48 个谓词里只有 9 个能落到本项目的 schema 上，其余关系用项目一的结构化字段
做弱监督补齐（要求对象串真实出现在句子里才算样本）。

### 5.2 模型

CasRel（HBT 论文的级联指针结构）：

```
BERT 编码 → 主语起止指针 → 主语向量广播 → 关系专属的宾语起止指针
```

宾语指针的维度是 `(序列长度 × 关系数)`，一次前向即可同时判定多种关系。
原始代码是 torch 1.4 写的，本项目做了移植，改动见 `casrel_model.py` 顶部注释
（去除硬编码设备、改用 `binary_cross_entropy_with_logits`、重写解码避免跨句拼接、补 attention_mask）。

### 5.3 评估

严格按 `(subject, predicate, object)` 三元组完全匹配计算 P/R/F1，
指标写入 `output/metrics.json` 与 `output/模型评估报告.md`，含分关系指标与错误样例。

**实际训练结果**（RTX 4060 8GB，batch 32，2 轮后早停，解码阈值 sub=0.70 / obj=0.50）：

| 数据集 | 样本 | P | R | micro-F1 | macro-F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| DuIE2.0 验证集 | 8,570 | 64.64% | 49.00% | **55.75%** | 36.05% |
| 目标领域测试集（未见人物） | 213 | 18.29% | 9.97% | 12.90% | 12.03% |

分关系看（dev）：毕业院校 80.3%、国籍 71.0%、演唱 69.6%、籍贯 67.7%、执导 60.4% 表现较好；
参演 43.5%（召回偏低，因为 DuIE 里「主演」句常列多位演员，而训练时每句只随机标注一个主语，
两轮训练覆盖不全）；职业 / 出生地 / 合作 / 民族 / 经纪公司 接近 0 —— 这几类在 DuIE 里没有，
只有几十到几百条弱监督样本，模型学不动。

**这正是保留规则抽取的原因**：这 5 类关系由项目一的结构化字段直接产出，置信度 0.95，
不依赖模型。目标领域测试集分数低，衡量的是「模型单独在这 5 类上的能力」，
不是最终图谱的质量。

阈值不是拍脑袋定的：`python tune.py` 在 dev 上对主/客体阈值做 5×5 网格搜索，
结果写入 `data/thresholds.json`，`extract.py` 自动读取。

## 六、三元组抽取与融合

`extract.py` 对每个词条融合三路结果，按置信度去重：

| 来源 | 置信度 | 说明 |
| --- | ---: | --- |
| 结构化字段 | 0.95 | 基本信息 / 主要作品 / 获奖记录，最准 |
| CasRel 模型 | 动态 | 正文句子上端到端抽取 |
| 句式模板 | 0.70 | 模型漏抽时兜底 |
| 同作品推导 | 0.75 | 两位人物参与同一作品 -> 合作 |

**实际产出**（212 个词条）：13,335 条三元组，其中结构化 9,213 条（69.1%）、
CasRel 2,283 条（17.1%）、模板 937 条（7.0%）、合作推导 941 条（7.1%）。

两条质量控制：

1. **主语白名单**：模型常把「该片」「中国内地」这类片段当成主语，
   只保留语料里真实存在的人物名，否则「人物」节点会从 213 个虚增到 1610 个；
2. **客体形态过滤**：作品类客体若超过 20 字或自带谓语动词（如把整句
   「用情的前奏采样自…」切成了歌名），直接丢弃；奖项名不套用这条，因为奖项名本就长。

作品标题列名在不同词条里五花八门（作品名 / 歌曲名称 / 节目名称…），
`rules._title_column` 会先按关键词识别，认不出来再按「哪一列最像标题」打分。

## 七、图数据库

**已接入真实 Neo4j 并完成导入**：Neo4j Enterprise 5.3.0，`bolt://localhost:7690`，
账号 `neo4j / kgproject123`，图规模 **10,271 节点 / 13,335 关系**，14 种关系类型全部落库。

```bash
python start_neo4j.py          # 启动（Ctrl+C 停止）
python start_neo4j.py --check  # 测连接并打印图规模

```

配置在 `config.py`：

```python
NEO4J_URI = "bolt://localhost:7690"
NEO4J_USER = "neo4j"
NEO4J_PASSWORD = "kgproject123"
```

没有启动 Neo4j 时，`store.get_store()` 会自动回退到本地图存储（`data/graph_local.json`），
流程不会中断，只是 Cypher 页只支持预设查询。

> 两处踩过的坑（详见 [`docs/Neo4j接入说明.md`](docs/Neo4j接入说明.md)）：
> 1. 这套 5.3 发行版的 `bin\neo4j.bat` 在 PowerShell 5.1 下报「已添加了具有相同键的项」起不来，
>    所以用 `start_neo4j.py` 直接调 java 主类，并且**必须在 bin 目录下执行**（它按上一级推算 home）；
> 2. 企业版要设 `NEO4J_ACCEPT_LICENSE_AGREEMENT=yes`，而且多一个 **routing 连接器**默认占 7688，
>    与 Desktop 实例冲突时要一起改端口。

## 八、GUI 功能

```bash
python main.py gui
```

| 标签页 | 功能 |
| --- | --- |
| 文本抽取 | 输入任意文本，展示抽取出的三元组（主体/关系/客体/置信度/来源），可导出 CSV、可存入图谱 |

界面在高分屏下会自动声明 DPI 感知，文字为原生渲染。
`output/screenshots/` 下有四张界面效果图，可直接放进报告。

> **启动顺序说明**：模型加载（import torch/transformers + 读 400MB BERT 权重，约 5~10 秒）
> 放在 `tk.Tk()` **之前**完成，所以窗口一出现就是就绪状态。
> 反过来（先建窗口再在主线程里加载）Tk 消息循环会停 5 秒以上，Windows 直接把标题栏改成「未响应」；
> 放子线程加载又会和 Tk 主循环并发触发段错误（exit 139）。图存储只做网络 I/O，才放子线程。

## 九、常见问题

- **显存不足**：把 `config.BATCH_SIZE` 调到 16 或 8，或 `MAX_LEN` 调到 128。
- **训练太慢**：先用 `--limit 2000 --epochs 1` 验证流程，再跑全量。
- **某些关系 F1 为 0**：`民族 / 经纪公司` 的弱监督样本只有几十条，模型学不动，
  这类关系实际由结构化字段（置信度 0.95）覆盖，属预期行为。
- **Neo4j 连不上**：`store.get_store()` 会自动回退到本地图存储并在日志里告警，不会中断流程。
- **`python gui.py` 打开后窗口「未响应」**：已修复。原因是模型加载放在主线程且晚于建窗口，
  Tk 消息循环停 5 秒以上 Windows 就判定无响应。现在改成**先把模型加载完再建窗口**，
  启动时控制台会打印 `[1/2] 正在加载关系抽取模型…`，约 5~10 秒后窗口才出现，出现即就绪。
  Neo4j 驱动的连接超时也从默认 30 秒压到 3 秒，服务没起时不会长时间卡住。
